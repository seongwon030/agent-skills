# wrap

## 1. 제출 체크 — 실행해서 확인, 추측 금지

각 항목에 실행한 명령과 결과를 붙여 보고한다.

- 과제 안내가 요구한 파일명·경로가 모두 있는가 (`ls`로 확인)
- 서버가 있다면 `0.0.0.0`에 바인딩됐고 실행 중인가 (`curl`로 확인)
- 테스트 전체 1회 실행 → 결과
- `git status`가 깨끗한가, `git log --oneline`이 요구사항 단위로 읽히는가
- 키·토큰이 파일에 없는가: `git grep -nIiE 'sk-[A-Za-z0-9_-]{20,}|api[_-]?key *[:=]|secret *[:=]'; git ls-files | grep -E '(^|/)\.env'`
- `AGENTS.md`의 완료 기준 ↔ 실제 결과 대조. 못 채운 것은 "한계"로 솔직히 적는다

결과를 `NOTES.md` 끝에 `## [HH:MM] 제출 체크` 블록으로 **append** 한다 (기존 블록은 고치지 않는다). 시각은 `date +%H:%M`.

## 2. RECALL.md — 서술형 대비

`NOTES.md`의 "틀리면 깨지는 것"·"못 한 것"·"사용자가 고친 것"에서 약점을 뽑는다. **최대 5개, NOTES에서 나온 만큼만.** 각 항목은 3단:

```
## N. <약점 위치: 파일:줄 또는 결정 이름>
- 왜 위험한가·파급: …
- 다음에 검증·개선할 것: …
- 근거: NOTES.md [HH:MM] <단계>
```

위치의 `파일:줄`은 `grep -n`으로 확인한 것만 적는다. `NOTES.md`에 없는 약점을 새로 만들지 않는다. 3개뿐이면 3개다.
마지막에 `docs: 제출 체크·RECALL 작성 / 검증: <테스트 명령>`으로 커밋한다. 막히면 명령을 출력해 사용자에게 넘긴다.

## 3. 사용자에게

"RECALL.md를 지금 읽으세요. 서술형은 AI·복사붙여넣기 금지입니다."라고 한 줄 남기고 끝낸다.
