# wrap

## 1. 제출 체크 — 실행해서 확인, 추측 금지

각 항목에 실행한 명령과 결과를 붙여 보고한다.

- 과제 안내가 요구한 파일명·경로가 모두 있는가 (`ls`로 확인)
- 서버가 있다면 `0.0.0.0`에 바인딩됐고 실행 중인가 (`curl`로 확인)
- 테스트 전체 1회 실행 → 결과. 실패가 있으면 `NOTES.md` "못 한 것"에 기록
- `git status`가 깨끗한가, `git log --oneline`이 요구사항 단위로 읽히는가
- 키·토큰·개인정보가 파일에 없는가 (`grep -ri "api_key\|secret\|token" --exclude-dir=node_modules .` 등)
- `AGENTS.md`의 완료 기준 ↔ 실제 결과 대조. 못 채운 것은 "한계"로 솔직히 적는다

## 2. RECALL.md — 서술형 대비

`NOTES.md`의 "틀리면 깨지는 것"·"못 한 것"·"바꾼 것"을 모아 **약점 5개**를 뽑는다. 각 항목은 반드시 3단:

```
## N. <약점이 있는 위치: 파일/함수/결정>
- 왜 위험한가·파급: …
- 다음에 검증·개선할 것: …
- 근거: NOTES.md [HH:MM] <단계>
```

추측으로 채우지 않는다. `NOTES.md`에 없는 약점을 새로 만들지 않는다.
마지막에 `docs: 제출 체크·RECALL 작성`으로 커밋한다.

## 3. 사용자에게

"RECALL.md를 지금 읽으세요. 서술형은 AI·복사붙여넣기 금지입니다."라고 한 줄 남기고 끝낸다.
