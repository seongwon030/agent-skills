# log

## 기본 (`$log`)

`NOTES.md`가 없으면 만든다(`$kickoff`가 보통 먼저 만든다). 방금 끝난 단계에 대해 파일 끝에 아래 블록을 **append** 한다. 기존 블록은 고치지 않는다.

```
## [HH:MM] <단계 이름>

### 결정
- 선택: … / 대안: … / 이유: … / 되돌릴 조건: …   (결정이 없었으면 "없음" 한 줄)

### 사용자가 고친 것
- 사용자: "<발화 짧게 인용>" → 바꿈: …   (이번 대화에서 사용자가 거절·수정한 경우만. 없으면 "없음")

### 깨지는 입력 3가지
1. … → 테스트: <파일:줄> → 결과: 통과 / 실패 / 미확인
2. …
3. …

### 검증
- 실행: `<명령>` → 결과: <출력 요약, 실패 수 포함>
- 못 한 것: …

### 틀리면 깨지는 것
- …
```

규칙 — 전부 "지어내지 않기" 위한 것이다:

- 시각은 `date +%H:%M`을 실행해서 얻는다.
- "결과"는 **이번 턴에 실행한 명령의 출력**에서만 가져온다. 안 돌렸으면 "미확인" 또는 "못 한 것"에 쓴다.
- "테스트: 파일:줄"은 `grep -n`으로 존재를 확인한 뒤 적는다. 없는 테스트를 이름으로 대지 않는다.
- "깨지는 입력 3가지" 중 최소 하나는 테스트 코드나 명령으로 실제 확인한다.
- "사용자가 고친 것"은 Codex 자신의 제안 변경을 적는 칸이 아니다. 사용자 발화가 없으면 "없음".
- 블록을 쓴 뒤 **커밋한다.** 메시지는 `<무엇> / 검증: <명령>` 한 줄이고, `<명령>`은 위 "검증" 줄의 명령을 그대로 옮긴다. 샌드박스나 승인에 막히면 명령을 출력해 사용자에게 넘긴다.

## 요약 (`$log sum`)

맥락이 길어졌을 때. `NOTES.md` 맨 위 `## 현재 상태` 절을 갱신한다: 끝난 단계 / 진행 중 / 남은 단계 / 열린 질문 / 다시 띄우는 명령(이번 세션에서 실행이 확인된 것만). 새 세션은 이 절부터 읽는다.
