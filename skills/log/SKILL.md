# log

## 기본 (`$log`)

방금 끝난 단계에 대해 `NOTES.md` 끝에 아래 블록을 **append** 한다. 기존 블록은 고치지 않는다.

```
## [HH:MM] <단계 이름>

### 결정
- 선택: … / 대안: … / 이유: … / 되돌릴 조건: …

### AI 제안 중 바꾼 것
- 제안: … → 바꿈: … / 왜: …   (없으면 "없음")

### 깨지는 입력 3가지
1. … → 테스트: <파일:함수 또는 명령> → 결과: 통과 / 실패 / 미확인
2. …
3. …

### 검증
- 실행: `<명령>` → 결과: <요약, 실패 수 포함>
- 못 한 것: …

### 틀리면 깨지는 것
- …
```

규칙:

- **증거 없는 항목 금지.** "검증"에는 실제로 실행한 명령과 그 출력 요약만 쓴다. 안 돌렸으면 "못 한 것"에 쓴다.
- "깨지는 입력 3가지"는 적기만 하지 말고, 셋 중 최소 하나는 테스트 코드나 명령으로 실제 확인한다. 확인 안 한 것은 "미확인"으로 둔다.
- 블록을 쓴 뒤 커밋을 제안한다. 메시지는 `<무엇> / 검증: <어떻게>` 한 줄. 요구사항 단위로 작게.

## 요약 (`$log sum`)

맥락이 길어졌을 때. `NOTES.md` 맨 위 `## 현재 상태` 절을 갱신한다: 끝난 단계 / 진행 중 / 남은 단계 / 열린 질문 / 다시 띄우는 명령. 새 세션은 이 절부터 읽는다.
