# kickoff

코드를 쓰지 않는다. 이 스킬의 산출물은 `AGENTS.md` 하나다.

## 순서

1. `README.md`·과제 안내·사용자가 전해 준 실무자(업무 담당자) 답변을 읽고, 요구사항을 **내 말로** 3줄 이내로 다시 쓴다. 안내에 없는 것은 "가정"으로 분리해 표시한다.
2. 완료 기준을 측정 가능하게 쓴다. 예: "입력 X에 출력 Y", "`GET /health` 200". 과제가 요구한 **제출 파일명**(코드·문서 모두)을 완료 기준에 목록으로 적는다. 과제가 계획·결정 문서의 파일명을 지정했으면 그 이름을 적어 두고, `$wrap`이 `AGENTS.md`·`NOTES.md` 내용을 그 파일로 복사한다.
3. 제약을 적는다: 언어·라이브러리, 입력 범위, 보안, 실행 환경. 템플릿의 기본값 줄은 과제 안내와 다르면 지운다. 언어·프레임워크·라이브러리가 안내에 없으면 고르지 말고 **후보 2개를 이유·설치 비용과 함께 "가정과 모르는 것"에 적어** 사용자가 고르게 한다. 표준 라이브러리로 되는 일에 외부 의존성을 제안하지 않는다.
   과제가 최적화·방식 선택(경로·배정·스케줄링 등)이면 목표 절의 세 줄을 채운다: **비용**(무엇을 잃으면 손해인가), **하드 제약**(어기면 답이 무효인 것, 예: 정원 45명·탑승 15분 이내), **최적화 목표**(제약 안에서 최대·최소로 할 것). 제약과 목표를 한 줄에 섞지 않는다. 해당 없는 과제면 세 줄을 지운다.
4. 작업을 3~6단계로 나눈다. 단계마다 산출물과 **검증 방법(실행할 명령 또는 케이스)** 을 적는다. 과제가 방식 비교를 요구하면 같은 입력으로 두 방식을 돌려 목표·제약 지표(예: 버스 대수·총 거리·최대 탑승 시간)를 표로 남기는 단계를 넣는다.
5. 가정과 모르는 것을 목록으로 내고 **멈춘다**. 모르는 것 중 과제 쪽에 물어볼 수 있는 것은 "실무자에게 물을 질문"으로 따로 묶는다. 이 턴은 여기서 끝낸다 — 같은 턴에 6~8번을 진행하지 않고, `NOTES.md` 생성·커밋도 하지 않는다. 사용자가 답하거나 고치기 전에 구현으로 넘어가지 않는다.
6. 사용자가 고친 내용이 있으면 반영하고, 고친 이유를 "가정과 모르는 것" 아래에 사용자 발화를 짧게 인용해 한 줄씩 남긴다. 사용자가 그대로 승인했으면 "수정 없음"이라고 쓴다. 꾸며내지 않는다.
7. `NOTES.md`를 만들고 첫 줄에 `작업 루틴 스킬(kickoff·log·wrap)은 본인 공개 레포 https://github.com/seongwon030/agent-skills 에서 clone해 사용.`을 적는다. 도구 출처를 숨기지 않기 위한 것이다.
8. 템플릿 맨 위 주석을 지우고 `docs: 목표·제약·작업분해 확정`으로 커밋한다(`AGENTS.md`, `NOTES.md`). 막히면 명령을 출력해 사용자에게 넘긴다.

`AGENTS.md`가 이미 있고 과제 쪽 내용이 들어 있으면 지우지 않는다. 그 아래에 위 절들을 추가한다.

## 금지

- 계획 단계에서 파일 생성·의존성 설치
- 안내에 없는 요구사항을 가정 표시 없이 목표에 넣기
- 검증 방법이 비어 있는 단계
